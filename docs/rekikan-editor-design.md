# れきかん — 編集・レビューツール設計書

**バージョン:** v1.0  

---

## 1. ツール概要

### 1.1 目的

「れきかん」のカードとステージ（問題）を作成・編集・レビューし、アプリ用のJSONデータとしてエクスポートするためのWebベース管理画面。

### 1.2 形態

- Webブラウザで動作するSPA（Single Page Application）
- データはブラウザのインメモリで管理し、JSON形式でインポート/エクスポート
- バックエンドサーバー不要（静的ホスティングで動作可能）
- 将来的にバックエンドを追加する場合にも、データ構造はそのまま流用可能

### 1.3 ユーザー

- コンテンツ制作者（カードの作成・編集）
- レビュアー（内容の確認・ステータス変更）
- 開発者（データのエクスポート・デバッグ）

## 3. カード管理画面

### 3.1 一覧表示

カードの一覧をテーブル形式で表示する。

**表示カラム：**

| カラム | 内容 | ソート | 幅目安 |
|--------|------|--------|--------|
| 地域 | 地域ラベル（絵文字つき） | ◯ | 60px |
| 時代帯 | カラーバッジで表示 | ◯ | 80px |
| 種類 | アイコンで表示 | ◯ | 40px |
| 用語名 / 説明文冒頭 | name があれば name、なければ description の先頭30文字 | ◯ | 200px |
| 年代 | year_label | ◯ | 80px |
| ステータス | バッジ表示（色分け） | ◯ | 80px |
| 使用数 | このカードが含まれるステージの数 | ◯ | 50px |
| 操作 | 編集 / 複製 / 削除 ボタン | - | 100px |

**フィルタ機能：**

| フィルタ項目 | 操作 |
|-------------|------|
| 地域 | ドロップダウン（複数選択可） |
| 時代帯 | ドロップダウン（複数選択可） |
| 種類 | ドロップダウン（複数選択可） |
| カードタイプ | 用語カード / 説明文カード |
| レビューステータス | draft / ai_generated / reviewed / approved |
| テキスト検索 | name, hint, description を横断検索 |

**一括操作：**

チェックボックスで複数カードを選択し、以下の一括操作を実行できる。

- ステータスの一括変更
- 地域・時代帯の一括変更
- 一括削除

### 3.2 カード編集フォーム

カードをクリックすると、右側にスライドパネル（またはモーダル）で編集フォームが開く。

**フォーム構成：**

```
│  用語名:      [徳川家康          ]         │
│  年代:        [1603   ]                    │
│  年代ラベル:  [1603年           ]          │
│                                            │
│  ── 視覚タグ ──                            │
│  時代帯:      [近世 ▼]  ■ プレビュー色    │
│  種類:        [人物 ▼]  👤                 │
│                                            │
│  ── コンテンツ ──                          │
│  ヒント:                                   │
│  [関ヶ原の勝者。幕府を開いた初代将軍    ] │
│  ⚠️ 順番確定情報チェック                   │
│                                            │
│  解説:                                     │
│  [関ヶ原の戦いに勝利し、江戸幕府を開い  ] │
│  [た。約260年続く太平の礎を築いた。      ] │
│                                            │
│  ── レビュー ──                            │

│  • 江戸時代の将軍（前半） — 正解順: 1     │
│  • 全時代区分（通し） — 正解順: 11        │
│                                            │
│  [保存]  [キャンセル]                      │
└────────────────────────────────────────────┘
```

**説明文カードの場合：**

カードタイプを「説明文カード」に切り替えると、用語名フィールドが非表示になり、ヒントフィールドも非表示になる。解説フィールドがカード表面の文章として扱われるため、ラベルが「カード表示文」に変わる。

**ヒントの順番確定情報チェック：**

ヒント入力時に、以下のパターンを検出して警告を表示する自動チェック機能。

- 「○代目」「○代将軍」「第○代」のような序数表現
- 「○○年に」「○○世紀に」のような年代直接表現
- 「最初の」「最後の」のような順序確定表現

警告は保存を妨げない（確認用）が、レビューステータスを `approved` にする際には未解消の警告がないことを推奨表示する。

### 3.3 カード新規作成

一覧画面上部の「＋新規カード」ボタンから編集フォームを空の状態で開く。カードIDは `{region}_{era_band_short}_{name_romaji}` の形式で自動生成し、手動で編集可能にする。

**複製機能：** 既存カードの「複製」ボタンから、全フィールドをコピーした新規カードを作成できる。IDのみ末尾に `_copy` を付与。同じ時代帯の似たカードを量産する際に便利。

### 4.3 カード割当

**「既存カードから選択」ダイアログ：**

カード管理画面と同じフィルタ・検索機能を持つカード選択ダイアログを表示する。チェックボックスで複数カードを選択し、一括でステージに追加できる。追加時は年代（year）順に自動でcorrect_orderが設定される。

**カード構成の操作：**

| 操作 | 方法 |
|------|------|
| 正解順の変更 | ドラッグ&ドロップ、または手動で番号入力 |
| カードの除外 | 行の×ボタン（カードマスタからは削除されない） |
| カードの編集 | 行をクリックでカード編集パネルに遷移 |
| 年代順に自動整列 | 「年代順に並べ直す」ボタン |

### 4.4 新規ステージ作成

ツリー画面の「＋新規ステージ」または、既存ステージの右クリックメニュー「子ステージを追加」から作成。親ステージの地域を自動で引き継ぐ。

## 6. JSON インポート / エクスポート

### 6.1 エクスポート

ヘッダーの「エクスポート」ボタンから、現在のデータ全体をJSON形式でダウンロードする。

**エクスポート形式：**

```jsonc
{
  "version": "1.0",
  "exported_at": "2026-04-01T10:00:00Z",
  "meta": {
    "regions_count": 3,
    "cards_count": 320,
    "stages_count": 45
  },
  "regions": [ ... ],
  "era_bands": [ ... ],
  "categories": [ ... ],
  "cards": [ ... ],
  "stages": [ ... ],
  "stage_cards": [ ... ]
}
```

**エクスポートオプション：**

| オプション | 説明 |
|-----------|------|
| 全データ | 全地域・全ステータスのデータ |
| approvedのみ | ステータスが approved のカード・ステージのみ（本番用） |
| 地域指定 | 特定地域のみエクスポート |

### 6.2 インポート

ヘッダーの「インポート」ボタンから、JSONファイルをアップロードして読み込む。

**インポート時の動作：**

| モード | 説明 |
|--------|------|
| 上書き | 現在のデータを全て破棄して、インポートデータで置き換え |
| マージ | 同一IDは上書き、新規IDは追加。削除は行わない |

**インポート前の検証：**

インポート前にデータの整合性チェックを行い、結果をダイアログで表示する。

| チェック項目 | 内容 |
|-------------|------|
| スキーマ検証 | 必須フィールドの存在、型の一致 |
| ID重複 | 同一エンティティ内でIDが重複していないか |
| 参照整合性 | card の region_id, era_band が regions, era_bands に存在するか |
| 参照整合性 | stage_cards の card_id, stage_id が実在するか |
| 親子整合性 | stage の parent_id が実在するか、循環参照がないか |
| カード枚数 | 各ステージのカード枚数が推奨範囲（5〜8枚）内か（警告のみ） |
| ヒントチェック | ヒントに順番確定情報が含まれていないか（警告のみ） |

## 7. バリデーションルール

編集・保存時に適用するバリデーション一覧。

### 7.1 カード

| ルール | 分類 | 内容 |
|--------|------|------|
| 必須フィールド | エラー | id, region_id, year, year_label, era_band, category, description, review_status |
| 用語カードの name | エラー | card_type が term の場合、name は必須 |
| ID形式 | エラー | 英数字・アンダースコアのみ、64文字以内 |
| ID一意性 | エラー | 全カード中で一意 |
| region_id 存在 | エラー | regions に存在する値 |
| era_band 存在 | エラー | era_bands に存在する値 |
| category 存在 | エラー | categories に存在する値 |
| ヒントの順番情報 | 警告 | 「○代目」「○○年」等のパターン検出 |
| ヒントと解説の重複 | 警告 | hint と description が80%以上一致 |

### 7.2 ステージ

| ルール | 分類 | 内容 |
|--------|------|------|
| 必須フィールド | エラー | id, region_id, title, card_type, depth, sort_order, unlock_rule, review_status |
| カード枚数 | 警告 | 5枚未満または9枚以上の場合（通しステージは例外） |
| カードの地域一致 | 警告 | ステージの region_id と含まれるカードの region_id が一致しない場合（横断問題は例外） |
| 親ステージ存在 | エラー | parent_id が指定されている場合、stages に存在する値 |
| 循環参照 | エラー | 親子関係が循環していないか |
| unlock対象存在 | エラー | unlock_rule.stage_ids の全IDが stages に存在する値 |
| 未approvedカード | 警告 | ステージを approved にする際、含まれるカードに未approved がある場合 |

## 8. 画面遷移と操作フロー

### 8.1 カード作成フロー

```
カード管理タブ → [＋新規カード] → 編集フォーム → 入力 → [保存]
                                                           ↓
                                              ステータス: draft
```

### 8.2 ステージ作成フロー

```
ステージ管理タブ → [＋新規ステージ] → 基本情報入力
                                        ↓
                                  [既存カードから選択] → カード選択ダイアログ → 追加
                                        ↓
                                  正解順の調整 → [保存]
```

### 8.3 レビューフロー

```
カード管理 → ステータスで "ai_generated" をフィルタ
           → カードをクリックして内容確認
           → ヒント警告を確認、必要に応じて修正
           → ステータスを "reviewed" → [保存]
           → （問題なければ）ステータスを "approved" → [保存]
```

### 8.4 エクスポートフロー

```
ヘッダー → [エクスポート] → オプション選択 → 検証実行 → 結果表示
                                                         ↓
                                              問題なし → JSONダウンロード
                                              警告あり → 確認して続行 or 修正
                                              エラーあり → 修正が必要
```

## 9. 技術構成案

### 9.1 フロントエンド

| 項目 | 選択肢 |
|------|--------|
| フレームワーク | React |
| UIライブラリ | Tailwind CSS + shadcn/ui |
| 状態管理 | React hooks（useState / useReducer） |
| ツリー表示 | カスタム実装またはreact-arborist |
| ドラッグ操作 | ステージツリーの並べ替え、カード正解順の並べ替えに使用 |

### 9.2 データ永続化

初期バージョンはバックエンド不要。以下の方式でデータを管理する。

| 方式 | 用途 |
|------|------|
| JSON インポート/エクスポート | データの保存・共有・バージョン管理 |
| ブラウザ IndexedDB | 作業中のオートセーブ（ブラウザ閉じても復帰可能） |

JSONファイルをGitリポジトリで管理すれば、変更履歴の追跡やチーム間のデータ共有が可能。

### 9.3 将来の拡張

バックエンドを追加する場合、JSON構造をそのままAPIのリクエスト/レスポンスに使用できる設計にしている。インポート/エクスポートのエンドポイントを設ければ、既存のJSON資産をそのまま移行可能。

## 10. 非機能要件

| 項目 | 要件 |
|------|------|
| 対応ブラウザ | Chrome, Safari, Firefox の最新2バージョン |
| レスポンシブ | デスクトップ優先（最低幅1024px）。モバイルは非対応でよい |
| パフォーマンス | カード1,000枚、ステージ300件で快適に動作 |
| オートセーブ | 変更があるたびにIndexedDBに自動保存。最終保存時刻を表示 |
| Undo | 直近の操作を1段階Undo可能（Ctrl+Z） |
